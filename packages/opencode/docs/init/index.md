# 初始化

本节说明如何为具体代码仓库启用 OpenCode：进入项目目录、启动 TUI，以及通过 `/init` 分析项目并在根目录生成 `AGENTS.md`。细节以 [官方文档 · Initialize](https://opencode.ai/docs#initialize) 为准。

## 先决条件

- 已完成 [安装](../setup)，终端可执行 `opencode`。
- 已完成 [配置](../config)，至少通过 `/connect` 绑定一家 LLM 提供商并可正常对话。

## 进入项目目录

在终端切换到你要协作的仓库路径。建议在**仓库根目录**操作，以便 `/init` 生成的 `AGENTS.md` 位于项目根部，供全仓库引用。

```bash
cd /path/to/project
```

若仅在子目录中开发，也可在该目录启动 OpenCode；但官方流程假定在根目录初始化，以便记录整体结构与约定。

## 启动 OpenCode

在项目目录下执行：

```bash
opencode
```

终端将进入 OpenCode TUI。首次进入某仓库时，建议先完成初始化再开始大规模改代码，这样后续提问与 Plan/Build 能利用项目上下文。

## 执行 `/init`

在 TUI 中输入：

```txt
/init
```

OpenCode 会分析当前项目的目录结构、技术栈与既有约定（如配置文件、常见模式），并在**项目根目录**创建或更新 `AGENTS.md`。

初始化过程中可继续与 OpenCode 对话；若仓库很大，分析可能花费片刻，属正常现象。

## `AGENTS.md` 的作用

`AGENTS.md` 是面向 AI 协作的**项目说明文件**，通常包含：

| 内容类型 | 说明 |
|----------|------|
| **项目结构** | 主要目录、模块划分与入口位置 |
| **技术栈与工具** | 语言、框架、包管理器、常用命令 |
| **编码约定** | 命名、测试、提交或团队约定（若可从仓库推断） |
| **协作提示** | 改代码时的注意点、禁改区域等 |

该文件帮助 OpenCode 理解「这个项目如何组织、应遵循哪些模式」，从而在解释代码、制定计划与直接修改时减少偏离。你可随项目演进手动编辑 `AGENTS.md`，或再次运行 `/init` 让 OpenCode 根据最新代码库更新。

**说明**：`AGENTS.md` 与 Cursor 等工具中的同名文件概念相近，但由 OpenCode 的 `/init` 生成，内容以当前仓库分析结果为准。若仓库已有 `AGENTS.md`，`/init` 可能合并或覆盖部分内容，执行前可先提交或备份本地修改。

## 初始化之后

完成 `/init` 后，即可在 TUI 中：

- **提问**：例如让 OpenCode 解释 `@path/to/file` 中的实现。
- **Plan / Build**：用 Tab 切换规划与执行模式，参见 [使用指南](../usage)。
- **撤销改动**：使用 `/undo`、`/redo` 回滚或重做编辑。

若更换了 LLM 提供商或模型，无需重新 `/init`；仅当项目结构或团队约定发生重大变化时，可再次运行 `/init` 刷新 `AGENTS.md`。

## 推荐阅读顺序

1. 确认 [配置](../config) 中 `/connect` 与 API Key 已就绪。
2. `cd` 到目标仓库根目录，执行 `opencode`。
3. 在 TUI 中运行 `/init`，检查根目录 `AGENTS.md` 是否符合预期并可选手动补充。
4. 阅读 [使用指南](../usage) 学习提问、Plan/Build 与改代码流程。

## 下一步

- 学习提问、规划与直接改代码，阅读 [使用指南](../usage)。
- 若尚未安装或配置，先完成 [安装](../setup) 与 [配置](../config)。
