# 使用指南

本节汇总在 OpenCode TUI 中的典型工作流：向代码库提问、在 **Plan 模式**下先出方案再在 **Build 模式**下落地、对明确需求直接改代码，以及用 `/undo`、`/redo` 回滚或重做变更。细节以 [官方文档 · Usage](https://opencode.ai/docs#usage) 为准。

## 先决条件

- 已完成 [安装](../setup) 与 [配置](../config)，TUI 可正常对话。
- 建议在目标仓库完成 [初始化](../init)（`/init` 与 `AGENTS.md`），以便 OpenCode 理解项目结构。

## 向代码库提问

可将 OpenCode 当作熟悉仓库的协作伙伴，请它解释你不熟悉的模块或文件。

在提示中引用文件路径（`@` 前缀），OpenCode 会读取对应内容再回答，例如：

```txt
@packages/functions/src/api/index.ts 里是如何处理认证的？
```

这对接手他人代码、快速摸清架构特别有用。路径相对于当前工作目录；尽量写清具体文件，避免过于笼统的「整个项目怎么写的」。

## Plan 模式与 Build 模式

添加较复杂功能时，官方建议先用 **Plan 模式**讨论方案，确认后再在 **Build 模式**下改文件。

### 切换到 Plan 模式

在 TUI 中按 **Tab** 切换到 Plan 模式。右下角会出现模式指示；此模式下 OpenCode **只规划、不直接修改文件**，便于你先审阅思路。

### 描述需求并迭代方案

用自然语言说明目标，像对团队里的初级开发者交代任务一样，给出足够上下文，例如：

```txt
用户删除笔记时，先在数据库里标记为已删除。
再做一个「最近删除」页面，可恢复或永久删除笔记。
```

收到方案后可以继续补充或修正，例如引用设计稿：

```txt
新页面请参考这张设计：[拖入图片]
```

可将图片**拖入终端**，OpenCode 会识别图像并纳入提示（官方支持在对话中附带截图等）。

### 切换到 Build 模式并执行

方案满意后，再按 **Tab** 切回 **Build 模式**，明确批准执行，例如：

```txt
可以，按这个方案改吧。
```

OpenCode 会按已讨论的方案编辑仓库中的文件。

| 模式 | 切换方式 | 行为 |
|------|----------|------|
| **Plan** | `Tab` → Plan | 只出计划，不改文件 |
| **Build** | `Tab` → Build | 可读写文件、执行改动 |

## 直接改代码（跳过冗长规划）

对范围清晰、改动较小的任务，可直接在 Build 模式下说明要做什么，无需先走完整 Plan 流程，例如：

```txt
给 /settings 路由加上认证。参考 @packages/functions/src/notes.ts 里 /notes 的做法，
在 @packages/functions/src/settings.ts 里实现相同逻辑。
```

提示越具体（涉及哪些文件、期望行为、参考实现），越能减少误改。引用 `@` 路径与 Plan 阶段一样有效。

## 撤销与重做：`/undo` 与 `/redo`

若 Build 阶段的结果不符合预期，可用斜杠命令回滚，再调整提示后重试。

### `/undo` 撤销上一轮改动

例如你让 OpenCode 重构某文件：

```txt
请重构 @packages/functions/src/api/index.ts 里的这个函数。
```

若结果不对，在 TUI 输入：

```txt
/undo
```

OpenCode 会**撤销该轮 AI 对文件所做的变更**，并回到你发出该请求前的对话状态，便于修改提示词后再次尝试。

### `/redo` 恢复被撤销的改动

若撤销后又想恢复刚才的修改，可输入：

```txt
/redo
```

`/redo` 会重新应用上一轮被 `/undo` 撤销的变更。

| 命令 | 作用 |
|------|------|
| `/undo` | 撤销最近一轮 AI 文件变更，回到对应提示前 |
| `/redo` | 恢复上一轮 `/undo` 撤销的变更 |

适合在「提示词差一点」时快速迭代，而不必手动 `git checkout` 每个被改文件（仍建议重要节点自行提交 Git）。

## 使用习惯小结

- **大功能**：Plan → 审阅与补充 → Build → 必要时 `/undo` 再改提示。
- **小改动**：Build 下写清文件与参考实现即可。
- **只读了解**：直接提问并 `@` 文件，无需切换模式。
- **协作复盘**：需要把对话给同事看时，见 [分享](../share) 的 `/share`。

## 推荐阅读顺序

1. 在已 [初始化](../init) 的仓库中启动 `opencode`。
2. 用 `@` 路径提问，熟悉解释代码的方式。
3. 试一次 Tab 切换 Plan → 描述需求 → Tab 回 Build 批准执行。
4. 故意做一次小改动，练习 `/undo` 与 `/redo`。
